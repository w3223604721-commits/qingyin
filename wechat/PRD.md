# 轻印（旅行记忆）产品需求文档

> 版本：内测 2.1 (Beta 2.1)  
> 更新日期：2026-06-09  
> 产品定位：轻量级旅行日记与足迹记录小程序

---

## 1. 产品概述

### 1.1 产品简介

轻印（Map + Memory）是一款面向旅行爱好者的轻量级旅行记录工具。用户可以通过地图打卡、日记撰写、照片管理等功能，将每一次旅行的足迹和记忆完整保留下来。产品核心理念是"在地图上留下脚印，用照片和文字珍藏记忆"——做减法，拒绝功能堆砌，只保留最核心的旅行记录能力。

### 1.2 目标用户

- 喜欢旅行并希望记录旅行足迹的年轻用户（20-40 岁）
- 对打卡记录、旅行日记有需求的自由行旅客
- 希望用简洁工具替代复杂旅行 App 的轻度用户

### 1.3 产品价值主张

- **简洁直观**：不做复杂功能堆砌，核心功能一目了然
- **地图驱动**：以地图为基底，让足迹可视化
- **记忆珍藏**：照片 + 文字 + 地理位置的完整记忆闭环
- **轻量分享**：支持小票风格等创意分享模板

### 1.4 技术栈

- 前端：原生 HTML/CSS/JavaScript（单页应用 SPA）
- 地图：Leaflet + 天地图瓦片
- 数据存储：浏览器 LocalStorage（本地存储）
- 图片导出：html2canvas
- 运行环境：微信小程序 / 移动端 H5

## 3. 功能详细说明

### 3.1 日志模块（Tab 1）

#### 3.1.1 旅程列表

| 属性 | 说明 |
|------|------|
| 触发 | 进入日志 Tab 自动加载 |
| 展示 | 旅程卡片列表，每张卡片含名称、城市、日期范围、简介、封面图 |
| 交互 | 点击卡片进入旅程详情；长按/菜单按钮弹出上下文菜单（编辑/删除） |
| 空状态 | 无旅程时展示引导文案 + 空状态插画 |

**旅程数据模型：**
```
{
  id: string,
  name: string,          // 旅程名称（必填，≤30字）
  city: string,          // 目的地城市（≤50字）
  startDate: string,     // 开始日期 YYYY-MM-DD
  endDate: string,       // 结束日期
  desc: string,          // 简介（≤200字）
  coverPhoto: string,    // 封面图片 Base64
  days: [],              // 日记条目数组
  createdAt: string,     // 创建时间 ISO
  tags: []               // 标签
}
```

#### 3.1.2 旅程详情

- **图片轮播**：从所有日记中提取照片，自动形成轮播（记忆点功能），支持左右滑动切换、指示点导航、计数器显示
- **日记列表**：按时间排序展示所有日记卡片，每张卡片含日期、标题、内容、照片预览
- **添加日记**：底部按钮，打开日记编辑模态框

#### 3.1.3 日记编辑

| 属性 | 说明 |
|------|------|
| 字段 | 日期、标题（≤30字）、内容（≤500字）、照片（最多50张） |
| 图片 | 支持拍摄/选取图片，带权限控制 |
| 编辑 | 可修改已有日记所有字段，支持删除日记 |

### 3.2 打卡模块（Tab 2）

#### 3.2.1 地图视图

- 使用天地图瓦片作为底图（Key: `b467feef6280075e4d11fad1ea502609`）
- 全屏展示，适配移动端
- 已打卡位置以标记点展示在地图上
- 支持缩放、拖拽等标准地图操作

#### 3.2.2 打卡操作

| 属性 | 说明 |
|------|------|
| 触发 | 地图右侧工具栏 "+" 按钮 |
| 字段 | 地点名称（必填）、城市、省份、照片、备注 |
| 定位 | 支持使用当前位置自动填充 |
| 图片 | 支持拍摄/选取，带权限控制 |

**打卡数据模型：**
```
{
  id: string,
  place: string,         // 地点名称（必填，≤30字）
  city: string,          // 城市
  province: string,      // 省份
  lat: number,           // 纬度
  lng: number,           // 经度
  photo: string,         // 照片 Base64
  note: string,          // 备注（≤200字）
  createdAt: string
}
```

#### 3.2.3 足迹记录

- **开始记录**：点击"开始记录"按钮后，持续追踪用户位置
- **足迹点**：定时记录 GPS 坐标，形成轨迹
- **停止记录**：再次点击停止，保存完整轨迹
- **回放功能**：左侧工具栏播放按钮，按时间顺序在地图上回放轨迹

### 3.3 分享模块（Tab 3）

#### 3.3.1 日志导出

- 从已有旅程列表中选择要导出的旅程
- 生成包含旅程信息的图片（封面图 + 日记摘要 + 照片）
- 支持保存到相册

#### 3.3.2 自定义模板（小票风格）

- **风格选择**：小票风格（已上线）/ 卡片风格（即将上线）/ 时间线（即将上线）/ 杂志风（即将上线）
- **自定义内容**：分享标题、选择 2-9 张图片、每张图片可配文字/地点/日期
- **预览与导出**：生成小票样式预览图，支持分享到微信/QQ 或保存相册

### 3.4 我的模块（Tab 4）

#### 3.4.1 个人资料

- 头像（支持拍摄/选取上传）
- 昵称（≤15字）
- 个性签名（≤50字）
- 旅行统计（旅程数、打卡数）

#### 3.4.2 勋章系统

- 基于中国 34 个省级行政区的打卡勋章
- 到达一个省份即点亮对应勋章
- 支持按"全部/已点亮/未点亮"筛选
- 展示点亮进度和完成百分比

#### 3.4.3 旅行人格

- 根据用户旅行数据自动判断旅行人格类型
- 如：探索者、打卡达人、城市漫游者等

#### 3.4.4 数据洞察

| 洞察维度 | 说明 |
|----------|------|
| 月度活跃 | 近 12 个月旅行活跃度柱状图 |
| 足迹增长 | 近 12 天足迹点统计折线图 |
| 季节分布 | 四季旅行偏好环形图 |
| 标签统计 | 标签使用频率统计 |

#### 3.4.5 设置

- **账号与安全**：展示账号类型（本地账户）、数据存储方式、设备 ID、创建时间
- **行程回收站**：恢复已删除的旅程（支持恢复和永久删除）
- **权限管理**：查看和重置通知/位置/照片/相机四项权限
- **开发者反馈**：问题反馈和功能建议提交表单
- **版本信息**：内测 2.0 Build 2026.06
- **清除所有数据**：一键清空（带确认，不可恢复）

## 4. 权限管理系统

### 4.1 权限类型

| 权限 | 触发时机 | 选项 |
|------|----------|------|
| 通知 | 首次进入应用 | 允许 / 不允许 |
| 位置 | 通知权限选择后 | 永不 / 下次询问 / 使用 App 期间 / 始终 |
| 照片图库 | 首次选取图片 | 不允许 / 受限访问 / 完全访问 |
| 相机 | 首次拍摄照片 | 允许 / 不允许 |

### 4.2 权限记忆机制

- 所有权限选择存储在 `localStorage` 中（Key: `qingyin_permissions`）
- 用户做出选择后，后续不再重复询问
- 可在设置 → 权限管理中查看当前权限状态并重置单项权限
- 重置后，下次使用对应功能时将重新询问

### 4.3 图片添加流程

所有图片添加入口统一改为"拍摄/选取图片"二选一模式：

```
用户点击"添加图片"
  → 弹出 ActionSheet：📸 拍摄 / 🖼️ 选取图片 / 取消
    → 拍摄：检查相机权限 → 打开相机
    → 选取图片：检查照片权限 → 打开相册
```

涉及位置：旅程封面、日记照片、日记详情照片、打卡照片、分享模板图片、头像上传

## 5. 非功能需求

### 5.1 性能要求

- 页面首次加载时间 ≤ 3 秒
- 图片列表渲染不卡顿（支持虚拟滚动）
- 地图加载与交互流畅（60fps）
- LocalStorage 读写操作不影响 UI 响应

### 5.2 兼容性

- 微信小程序 WebView 环境
- iOS Safari 14+
- Android Chrome 90+
- 移动端 H5 浏览器

### 5.3 数据安全

- 所有数据存储在用户设备本地（LocalStorage）
- 不涉及云端同步（当前版本）
- 提供导出/导入数据功能作为备份手段
- 删除数据有确认弹窗保护

### 5.4 UI/UX 规范

- 最大内容宽度 500px，移动端优先设计
- 底部导航栏高度 64px
- 主题色：`#6366F1`（靛蓝紫）
- 圆角体系：8px / 12px / 16px / 20px
- 字体：系统默认中文字体栈（PingFang SC / Microsoft YaHei）

## 6. 数据流与存储

### 6.1 数据结构

```javascript
{
  journeys: [Journey],      // 旅程数组
  checkins: [Checkin],      // 打卡数组
  footprintTracks: [],      // 足迹轨迹数组
  profile: {                // 用户资料
    name: string,
    bio: string,
    avatar: string|null
  },
  currentJourneyId: string|null,  // 当前浏览的旅程
  trash: [Journey],         // 回收站
  carouselIndex: {}         // 轮播位置记忆
}
```

### 6.2 存储方式

- 主数据：`localStorage` → Key `qingyin_data`
- 权限数据：`localStorage` → Key `qingyin_permissions`
- 图片：Base64 编码存储在主数据中

### 6.3 数据流转

```
用户操作 → 更新内存数据(appData) → 持久化到 localStorage → 刷新 UI
```

### 8.3 设计理念

轻印的设计哲学来源于对旅行记录痛点的洞察：

> "我们曾无数次在旅途中打开各种旅游日记、打卡工具，却总被复杂的功能劝退——明明只是想记下'今天去了哪里、看到了什么'，为什么需要填这么多表单？选分类、打标签、写攻略……这些真的有必要吗？"

因此轻印坚持以下原则：

1. **减法优先**：砍掉不必要的功能，只保留核心
2. **地图原生**：以地理坐标组织记忆，而非文件夹
3. **轻量体验**：无需注册、无需同步、打开即用
4. **权限透明**：所有敏感权限均主动告知用户用途
